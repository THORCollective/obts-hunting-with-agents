## LEARN: Prepare the Hunt

### Hypothesis Statement

Adversaries are executing unsigned or ad-hoc signed Mach-O binaries or scripts on our macOS fleet, often from user-writable locations (/tmp, /Users/Shared, ~/Library, Downloads), and persisting them via LaunchAgents/LaunchDaemons or login items, which will appear as ES exec events with target_signer=adhoc/other and btm_launch_item_add events pointing at non-developer-ID executables.

### Threat Context

Commodity macOS malware avoids notarization. It ships ad-hoc signed or unsigned, and the user is talked into running it past Gatekeeper with right-click Open or `xattr -d`.
- **Infostealers** (Atomic/AMOS, Cuckoo, Banshee families) pose as utility apps such as "CleanMyMac" cracks. They show an `osascript display dialog ... with hidden answer` password prompt, read the login keychain and browser stores, and bulk-POST to a single C2.
- **Backdoors** drop into hidden dirs under `/Users/Shared` or `~/Library` and persist through a LaunchAgent with an Apple-looking label (`com.apple.*`).
- **Developer supply chain:** malicious npm or PyPI packages run `postinstall` scripts. That code is unsigned, but it runs under a legitimately signed interpreter (node), so a signer-only filter misses it.

## OBSERVE: Expected Behaviors

### What Normal Looks Like

- Apple platform binaries (`*_signer=apple`) under /System, /usr, /bin, /sbin.
- Developer-ID apps in /Applications with a known Team ID (Chrome `EQHXZ8M8AV`, Node.js `HX7739G8FX`).
- **Ad-hoc signed but benign:** Homebrew bottles and its portable-ruby under `/opt/homebrew`, run from `brew` with brew-style LaunchAgent labels (`homebrew.mxcl.*`). Developer machines also have locally built tools.
- Browsers opening `login.keychain-db` at launch for their Safe Storage key.
- npm install scripts from well-known packages (node-gyp rebuilds) that only reach nodejs.org or registry.npmjs.org.

### What Suspicious Looks Like

- Ad-hoc or unsigned binaries running from `/Users/Shared`, hidden dirs, `/tmp`, or app bundles named like known vendor products but without that vendor's Team ID.
- Unsigned code spawning `osascript` password dialogs, or opening the keychain or browser credential stores.
- BTM or LaunchAgent creation where the executable is ad-hoc or unsigned, especially with a `com.apple.*` label.
- Signed interpreters (node, python, osascript) running scripts that make first-seen external connections, such as package install scripts.
- A single large outbound TLS upload to a rare domain right after credential access.

### Expected Observables

- **Processes:** `target_signer IN (adhoc, other)`, `target_team_id=none`; osascript `display dialog ... hidden answer`; `npm install` → `sh -c node scripts/postinstall.js`
- **Network:** rare single-host domains (`.top`, `.cc`), large orig_bytes, TLS to non-CDN IPs
- **Files:** `~/Library/LaunchAgents/*.plist` created by non-Apple processes; `login.keychain-db` opened by non-browser processes
- **Registry:** N/A (macOS)
- **Authentication:** openssh_login across fleet hosts near suspicious activity

## CHECK: Execute & Analyze

### Data Source Information

- **Index/Data Source:** `index=macos` (sourcetype `macos:eslogger`), `index=zeek` (`bro:*:json`)
- **Time Range:** 2024-06-11 14:00–16:00 UTC (whole corpus; queried with `--earliest 0`)
- **Events Analyzed:** 1,254 ES events (269 exec, 2 BTM, 4 create) across 6 hosts; ~4,100 Zeek records (1,746 conn, 797 dns, 766 ssl, 384 files, 1 pe)
- **Data Quality:** Filtered ES collector (163–251 events/host). There are no ES network events, so attribution to processes is by host IP plus timing. File creation of the cloudsyncd binary and the CleanMyMac app bundle is not in the corpus.

### Hunting Queries

All run as `athf splunk search '<SPL>' --earliest 0 --count 200 --format json`.

#### Initial Query: broad sweep of exec by signer class

```spl
index=macos es_event=exec | stats count by target_signer
index=macos es_event=exec target_signer!=apple
| lookup mac_hosts host OUTPUT host_short
| stats count values(host_short) as hosts values(target_team_id) as team
        values(target_signing_id) as sid values(process_path) as parent
  by target_signer target_path
```

**Query Notes:**
- apple 248 · developer_id 17 · adhoc 4. The four ad-hoc targets were CleanMyMacX Helper (MAC-DESIGN-01), /Users/Shared/.cloudsync/cloudsyncd (MAC-IT-01), Homebrew portable-ruby, and postgresql@16 (MAC-DEV-02). The developer_id targets were Chrome and node.
- A subject-side version (`process_signer!=apple`, any es_event) returned the same set, so no non-Apple process was already running before the window.
- Apple-signed execs outside the system paths returned nothing (no relocated or masqueraded platform binaries).

#### Refined Query 1: signed interpreters and LOLBins running staged or unsigned content

```spl
index=macos es_event=exec (cmdline="*/tmp/*" OR cmdline="*/Users/Shared/*" OR cmdline="*Downloads*"
  OR cmdline="*curl*" OR cmdline="*chmod*" OR cmdline="*xattr*" OR cmdline="*codesign*"
  OR cmdline="*launchctl*" OR cmdline="*osascript*" OR cmdline="*base64*" OR cmdline="*LaunchAgents*"
  OR cmdline="*LaunchDaemons*" OR cmdline="*spctl*" OR cmdline="*python*" OR cmdline="*.sh*")
| lookup mac_hosts host OUTPUT host_short | eval t=strftime(_time,"%H:%M:%S")
| table t host_short pid ppid process_path target_path target_signer cmdline cwd
```

**Notes:** Surfaced the osascript fake password prompt whose parent was CleanMyMacX Helper, `cloudsyncd --install`, brew's `launchctl bootstrap`, and the curl, pytest and `security find-identity` lookalikes.

#### Refined Query 2: persistence (BTM and file creates)

```spl
index=macos (es_event=btm_launch_item_add OR es_event=create)
| lookup mac_hosts host OUTPUT host_short | eval t=strftime(_time,"%H:%M:%S")
| table t host_short es_event pid process_path process_signer file_path btm_item_url
        btm_item_type btm_executable_path btm_instigator_pid btm_instigator_path btm_instigator_signing_id
```

**Notes:** There were two BTM adds. One is benign (homebrew.mxcl.postgresql@16). The other is suspicious: `com.apple.cloudsyncd.plist`, pointing at the ad-hoc /Users/Shared binary.

#### Refined Query 3: ancestry pivot (per host, by pid/ppid/child_pid)

```spl
index=macos host=<HOST>* (pid IN (<pids>) OR ppid IN (<pids>) OR child_pid IN (<pids>)
  OR file_path="*<name>*" OR cmdline="*<name>*")
| eval t=strftime(_time,"%H:%M:%S") | sort _time
| table t es_event pid ppid uid process_path child_pid target_path target_signer cmdline file_path
```

**Notes:** cloudsyncd's parent is login → `-zsh` (pid 827, Terminal session since 14:11:12Z). CleanMyMacX Helper's parent is launchd (user-launched app) → osascript, then a keychain open. The postinstall chain is zsh → node npm → sh → node postinstall.js.

#### Refined Query 4: network context via Zeek (host IP plus time window)

```spl
index=zeek ((id.orig_h=10.20.10.31 earliest=1718115700 latest=1718115900)
         OR (id.orig_h=10.20.10.33 earliest=1718119540 latest=1718119800))
| eval t=strftime(_time,"%H:%M:%S") | sort _time
| table t sourcetype id.orig_h id.resp_h id.resp_p proto service query server_name orig_bytes resp_bytes duration

index=zeek sourcetype=bro:dns:json NOT query="*.in-addr.arpa"
| stats dc(id.orig_h) as hosts values(id.orig_h) as src count by query | where hosts=1
```

**Notes:** The window query found the 2.45 MB upload to gateway.macos-analytics.top. The single-host DNS rarity list surfaced api.ipcheck-beaver.cc on 10.20.10.32, which I then tied back to the npm postinstall by timestamp.

#### Refined Query 5: credential stores and persistence paths, all writers

```spl
index=macos es_event IN (write,create,open) (file_path="*/LaunchAgents/*" OR file_path="*/LaunchDaemons/*"
  OR file_path="*.zshrc" OR file_path="*.zprofile" OR file_path="*crontab*" OR file_path="*/periodic/*"
  OR file_path="*login.keychain*" OR file_path="*Cookies*" OR file_path="*Login Data*")
| lookup mac_hosts host OUTPUT host_short
| stats count min(_time) as first by host_short es_event process_path process_signer file_path
```

### Query Performance

**What Worked Well:**
- The flat `*_signer` and `*_team_id` fields made the first sweep a single `stats`.
- BTM events carry instigator and executable, so persistence attribution took one query.
- Single-host DNS rarity in Zeek caught the npm finding, which the signer sweep cannot see.

**What Didn't Work:**
- The oneshot search silently caps at 100 rows, so I had to page the rarity list with a `where query>"..."` cursor.
- Zeek `files` multivalue fields (`tx_hosts{}`) did not filter or `mvjoin` cleanly, so I fell back to `_raw`.
- The first epoch window for the 14:51 Zeek lookup was miscalculated (14:00:00Z = 1718114400 is the anchor).

**Iterations Made:**
- Signer sweep → subject-signer sweep → cmdline LOLBin sweep → BTM/create → per-host ancestry → Zeek window join → fleet DNS rarity → reverse join DNS hit to ES by time → lookalike validation (brew, bcrypt, Chrome, DBeaver, SSH, security).

## KEEP: Findings & Response

### Executive Summary

The hypothesis is supported. Unsigned or ad-hoc code executed on 3 of 6 Macs, and on one of them it persisted.
1. **MAC-DESIGN-01:** a fake, ad-hoc "CleanMyMacX Helper" showed a fake password prompt, opened the login keychain, and uploaded 2.45 MB to `gateway.macos-analytics.top` (193.42.33.14). This looks like an infostealer.
2. **MAC-IT-01:** an ad-hoc binary in hidden `/Users/Shared/.cloudsync/` installed an Apple-masquerading LaunchAgent (`com.apple.cloudsyncd`). This looks like a backdoor.
3. **MAC-DEV-01:** an npm package whose scope matches the company name (`@clearwater-ui/react-icons-pro`) ran a postinstall script that fetched about 96 KB from `api.ipcheck-beaver.cc` (45.128.199.72). This looks like a supply-chain or dependency-confusion attack.

All three are `suspected` (telemetry only). Eight benign lookalikes were ruled out with signer, path, ancestry and network evidence.

- **Allowlist for ad-hoc/Developer-ID noise:**

- **Gotchas:**

### Lessons Learned

**What Worked Well:**
- Starting from the signer field and then forcing ancestry plus Zeek on every hit separated the 4 ad-hoc execs into 2 malicious-looking and 2 Homebrew within a few queries.
- Network rarity found a finding that code-signing telemetry structurally cannot.

**What Could Be Improved:**
- Add a scheduled detection for `btm_launch_item_add` where the executable signer is adhoc or other, or where the label is `com.apple.*` and the executable is outside /System and /usr.
- Add a detection for `osascript` with `hidden answer` whose parent is not Apple-signed.

**Telemetry Gaps Identified:**
- There are no ES network events, so process-to-connection attribution is by timing only.
- The collector filter dropped the create/write events that would show how cloudsyncd and the CleanMyMac bundle arrived (download source, quarantine xattr).
- There are no file hashes or content, so the binaries, plist and npm tarball cannot be assessed.
- The corpus covers a 2-hour window only, so cloudsyncd's LaunchAgent firing at next login and any later beaconing are not visible.
